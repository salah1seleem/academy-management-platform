## بيئة العرض

استخدم قاعدة Demo مستقلة ومطبّقًا عليها migrations القائمة وإعدادات README، مع `Demo__SeedProfile=Football` (الافتراضي). الأكاديمية المحجوزة `30000000-0000-0000-0000-000000000003`، slug `football-demo`. تشغيل عادي على قاعدة موجودة لا يحذف أي أكاديمية قديمة ولا يعيد بيانات معدّلة؛ الحسابات أدناه تنتمي لأكاديمية العرض فقط. الأفضل قاعدة جديدة للعرض النظيف. `LegacyRegression` يُستخدم صراحة في اختبارات الويب/backend متعددة الرياضات والعزل، ولا يُزرع تلقائيًا في العرض.

تاريخ العرض `Demo__ReferenceDate=2026-09-28`. رياضة كرة القدم فقط؛ الفروع: **فرع مدينة نصر، فرع مدينتي، فرع الشروق**. 6 مجموعات مواليد 2018–2013، 4 مدربين بحسابات وهواتف منفصلة، 30 لاعبًا بأكواد `FB-0001`–`FB-0030`، و29 ولي أمر بروابط صريحة. 10 اشتراكات نشطة بعيدة عن الانتهاء، 10 تنتهي قريبًا و10 منتهية؛ 30 تحصيلًا وإيصالًا، دفع معلق وآخر فاشل، 24 جلسة و90 سجل حضور لاعب و18 حضور مدرب، 30 تقييمًا منشورًا ومسودة. الأرقام مشتقة من السجلات لا من hardcoded dashboard totals.

كلمة مرور موظفي **Demo فقط**: `Demo-Only-123!`. رمز OTP: `246810`. كود المستفيد التجريبي `RNW-DEMO-FB-0030-8J7P`، ينتهي بعد عامين من تاريخ المرجع؛ دفعه لا ينشئ علاقة ولي أمر. لا تستخدم الحسابات أو الرمز الثابت خارج Demo.

رحلة الويب: المالك ← لوحة المالك ← اللاعبون/الفروع/المجموعات ← المدربون ← إضافة مدرب. الاسم والهاتف إلزاميان؛ البريد والإسناد اختياريان. إنشاء المدرب يحفظ الهوية والعضوية والإسناد ذريًا، ويتيح OTP للموبايل عند نشاط الحساب. لا كلمة مرور مشتركة ولا تغيير لهوية موجودة. نفس الهاتف normalized يعيد استخدام الهوية فقط عند تطابق البيانات؛ أي اختلاف يتطلب مراجعة ولا يكشف بيانات الأكاديمية الأخرى. تكرار الحفظ المطابق لا يكرر العضوية. لإدارة الإسناد لاحقًا استخدم «إسناد مجموعة» القائمة.

رحلة Guardian Flutter: هاتف ← OTP ← الرئيسية والإجراءات الثلاثة ← ملف الطفل ← التقرير/المواعيد/الحضور/التغذية/الطب/المعرض ← طلب اشتراك أو تجديد ← دفع Demo ← إيصال. التجديد للغير يستخدم الكود opaque ولا يضيف الطفل للحساب. الخادم وحده يحسب التقييم والاشتراك والمال، والكتابة idempotent ولا تُعاد تلقائيًا. المسارات الخاصة تزول مع logout/تبديل العضوية. Coach/Owner التجاريان لم ينفذا بعد. إعداد SMS الحقيقي غير متوفر؛ خارج Demo يرجع `501`.

## إعادة تهيئة آمنة — DM-12

**أوقف API العرض قبل reset. هذا يمحو تعديلات العرض داخل الأكاديمية المحجوزة فقط ويعيد seed؛ لا يمس الأكاديميات الأخرى أو الهويات العامة.** نفّذ من جذر المشروع مع connection محلي مؤكد وDemo environment محمّلين مسبقًا، وليس production:

```bash
Demo__ResetConfirmation=football-demo-only dotnet run \
  --project apps/api/src/Academy.Api --no-launch-profile -- --reset-football-demo
```

العملية تتطلب `Demo` و`SeedEnabled=true` وprofile `Football`، وثلاث علامات متطابقة مخزنة: ID المحجوز + slug + `EnglishName=Football Demo Dataset v1`، إضافة إلى التأكيد الصريح. إذا لم يسبق seed أو تغيّرت العلامة ترفض العملية. لا يقبل الأمر AcademyId اختياريًا ولا ينفذ drop/truncate. داخل transaction وقفل advisory: يلغي جلسات الويب/native المرتبطة بأكاديمية العرض، يحذف سجلاتها التابعة بترتيب FK، ثم يعيد المعرفات والسجلات المحددة. فشل أي خطوة يرجع العملية كلها. بدء API المعتاد ليس reset.

تبقى `Users` وكلمات المرور/security stamps كما هي لحماية أي عضوية في أكاديمية أخرى؛ المدرب المضاف يدويًا يفقد عضويته في ديمو العرض بعد reset، لكن هويته العامة لا تُحذف. لذلك التكرار deterministic للسجلات الخاصة بأكاديمية العرض، وليس وعدًا بمحو كل هوية/OTP عالمية. أي تضارب مع هوية محجوزة يرفض دون استبدال. تخطيط الإنتاج لم يتغير، ولا migration جديدة لهذه المرحلة.
