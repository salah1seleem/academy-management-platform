# نظام واجهة لوحة الموظفين

الحالة: مطبّق على واجهات `Owner` و`Admin` و`Coach`، مع تحديث Sports Academy بتاريخ 2026-10-04. لا تغيير لقواعد الأعمال أو أوامر الكتابة أو الصلاحيات؛ توسعت استجابات القراءة فقط بالبيانات اللازمة للبطاقات. هذا ليس إعادة تصميم لتطبيق ولي الأمر أو تنفيذ Flutter.

## الأساس البصري

- الخط: `Cairo` من `next/font/google` بالأوزان 400 و500 و600 و700، مع بدائل نظامية آمنة. النص الأساسي 14–15px، والبيانات المساندة 12–13px، وعنوان الصفحة 24–30px.
- الألوان: `athletic teal` داكن، `emerald #168566`، لمسات `gold #e8bc58` و`sky #3185b4`، سطح أبيض وخلفية `#f0f5f2`. ألوان الحالات دلالية بنص وأيقونة، بلا اتجاهات أو بيانات تجميلية مختلقة.
- الرموز: `lucide-react` بنمط موحد. لا تُستخدم الرموز بدل النص عندما يؤثر ذلك في وضوح المعنى أو إمكانية الوصول.
- المسافات: إيقاع 4، 8، 12، 16، 20، 24، 32، 40px. أنصاف الأقطار 8px لعناصر التحكم، 16px للبطاقات و22px للأسطح الكبيرة. الظلال خفيفة ويعتمد الفصل أساسًا على الحدود.

توجد المتغيرات البصرية داخل `.dashboard-shell` في `dashboard.css` حتى تبقى تغييرات لوحة الموظفين معزولة عن واجهة ولي الأمر.

## المكوّنات

- `DashboardShell`: شريط جانبي داكن بعرض 276px، علامة الأكاديمية، هوية المستخدم ودوره، مجموعات تنقل واضحة، وحساب/خروج ثابت في الأسفل. الوحدة الحالية مفتوحة تلقائيًا ويظهر المسار النشط عبر `aria-current` ومؤشر بصري.
- `PageHeader`: سياق مختصر، عنوان، وصف اختياري، وإجراءات أساسية/ثانوية مرتبة وتتحول إلى صفوف على الشاشات الصغيرة.
- `Button`: أنماط `primary` و`secondary` و`ghost` و`danger` بارتفاع 42px وحالات تركيز وتعطيل متسقة.
- `StatusBadge`: ترجمة حالات النظام إلى العربية مع نبرة دلالية ونص ظاهر؛ اللون ليس وسيلة التمييز الوحيدة.
- `FilterToolbar` و`SearchInput`: يجمعان البحث والفلاتر وعدد النتائج وإعادة الضبط في سطح واحد قابل للالتفاف.
- `AdminDataTable`: أعمدة مصطفة ورأس وجدول كثيف على الشاشات الكبيرة، ونفس البيانات كبطاقات معنونة على الهاتف. يسمح بالتمرير الأفقي داخل سطح القائمة فقط عند الحاجة في المقاسات الوسطية.
- `RowActions` و`RowActionMenu`: الإجراء الأساسي ظاهر، والإجراءات الإضافية داخل قائمة وصول واضحة؛ إجراءات الخطر منفصلة بصريًا.
- `MetricCard` و`SectionCard`: هرمية متباينة للمؤشرات الرئيسية والثانوية وأقسام التقارير دون إضافة بيانات أو اتجاهات وهمية.
- `FormSection`: تجميع دلالي للنماذج الطويلة مع عنوان ووصف وشبكة عمودين تتحول إلى عمود واحد.
- `LoadingState` و`EmptyState` و`ErrorState` و`ConfirmationDialog`: حالات موحدة، نص واضح، وتركيز ولوحة مفاتيح للحوار.

## الاستجابة وإمكانية الوصول

- من 1152px: الشريط الجانبي ثابت ومستقل التمرير، والمحتوى يستغل المساحة الباقية.
- أقل من 1152px: يتحول الشريط إلى drawer بغطاء وإغلاق بزر أو `Escape` مع إعادة التركيز إلى زر الفتح.
- أقل من 768px: تتحول الجداول إلى بطاقات معنونة، وتتكدس الأدوات والنماذج والإجراءات دون تمرير أفقي للصفحة.
- حالات التركيز مرئية، والأزرار اللمسية لا تقل عادة عن 40–44px، والحقول مرتبطة بتسميات، والقوائم والحوارات تحمل دلالاتها المناسبة.

أي واجهة موظفين جديدة ينبغي أن تعيد استخدام هذه المكوّنات والمتغيرات، وأن تعرض القيم الحقيقية المخزنة فقط، وأن تحافظ على العربية وRTL والعقود والصلاحيات الحالية.

## Sports Academy — Phase UI

- `SportsHero` يستخدم اسم المستخدم والأكاديمية ومرجع التقرير من الخادم. خطوط الملعب هنا زخرفة صامتة للوحة الموظفين، وليست مخطط مراكز في تقرير الطفل.
- لوحة المالك: أربعة مؤشرات رئيسية وستة مساندة؛ تحصيل الفروع/الرياضات بأشرطة، وحضور اليوم بحلقة من السجلات المحفوظة فقط. غياب السجلات يعرض empty state، لا نسبة وهمية. مؤشرات حالة الاشتراك مستقلة لأن الفعالة والمنتهية قريبًا قد تتداخلان.
- `SportsQuickActions`: التسجيل والتجديد والحضور والتقييم والمالية لـOwner/Admin. إضافة مدرب تنتظر تنفيذ Phase B ولا يظهر لها زر ميت. المدرب يحتفظ بالحضور والتقييم وتقارير الحضور فقط، دون المالية أو إنشاء/إنهاء الجلسات غير المخولة.
- `IdentityMark`: صورة Demo محلية آمنة إن توفرت؛ وإلا أحرف الاسم، لا صور أطفال عشوائية ولا صور خارجية. ملف اللاعب يعرض العمر وفق تاريخ السجل، المركز والقدم والطول/الوزن، كل تسجيل واشتراك على حدة، وروابط أولياء الأمور الفعلية والسجلات المختصة.
- قائمة اللاعبين تعرض فروع/مجموعات/حالات كل التسجيلات من استجابة واحدة؛ صفحات عرض 12 لاعبًا، دون طلب تفاصيل لكل صف. هذه pagination عرض محلية وليست ادعاء بوجود pagination خادمية جديدة.
- بطاقات المدربين تعرض الإسنادات والفروع؛ المجموعات تعرض المدرب والجدول والعدد المخزن. جلسات التدريب تعرض المدرب وتقدم تسجيل الحضور. الباقات بطاقات بالمدة/الحصص والسعر القائم؛ لا تغيير للتحصيل.
- `AttendanceChoice` يجمع النص والأيقونة و`aria-pressed`. `ProgressTrack` يعرض القيمة/الإجمالي؛ الصفر يبقى صفرًا. الـskeleton وhover وaccordion وfade-up كلها CSS خفيفة، مع تعطيل الحركة فعليًا عند `prefers-reduced-motion`؛ الأقسام المغلقة `inert` و`aria-hidden`.
- استجابات القراءة المضافة: `people/players.enrollmentSummaries`, تفاصيل اللاعب `asOfDate/guardians/photoReference`، مجموعات `coaches/schedules/playerCount`، مدربون `groups`، جلسات `coaches`. كل query فرعي مقيد بالأكاديمية والعلاقة؛ لا migration ولا تغيير endpoint writes أو auth أو قواعد session consumption/scoring.

بوابة المراجعة: Owner (الرئيسية/اللاعبون/الاشتراكات/الباقات/المالية)، Admin (اللاعبون/المجموعات/الجلسات/كشف الحضور/التقييمات/المحتوى)، Coach (الجلسات/كشف الحضور/التقييمات) عند `1440×900`, `1280×800`, `390×844`. الاختبار `sports-dashboard.spec.ts` يحفظ اللقطات ويكشف overflow وأخطاء الصفحة والتنقل غير المخول وreduced motion. اللقطات وحدها ليست دليل مراجعة؛ النتائج الفعلية في STATUS.
