# Decisions v1.0

## اختيار الأيام وفلاتر الفترة — 2026-10-08، CH-025

[v1.8](../requirements/ACADEMY_REQUIREMENTS_BASELINE_AR_v1.8.md) يحل محل فترة CH-024 ومسحها أدناه. تنسيق `WeekdaysField` معزول في CSS Module ذي أولوية واضحة على قواعد النموذج العامة؛ checkbox أصلي قابل للوحة المفاتيح داخل بلاطة صغيرة، بينما لون الخلفية يبيّن الاختيار دون مربع native ظاهر. قيم الأيام لم تتغير.

`monthToDate` يحسب أول الشهر/اليوم بتوقيت القاهرة الحقيقي. Dashboard Server Layout يمرر الفترة عبر context بعد `connection()` حتى لا تُجمّد بتاريخ build ولا تختلف بين الخادم والمتصفح. لا تغيير لساعة Demo أو ساعة الأمان. الرابط الصريح يحافظ على الفترة، ورد API لا يعيد ملء الحقول بعد المسح. التقارير المحدودة تنتظر فترة جديدة وتمنع تصديرًا بلا تاريخ؛ القوائم التي تدعم القراءة بلا فترة أصلًا تزيل القيد. لا API جديد ولا تغيير لعزل tenant أو حسابات التقارير أو تواريخ تحرير السجلات.

## إضافة 2026-10-04 — برنامج Native Mobile

> البنود الأصلية أعلاه سجل تاريخي. تعديلات المالك في 7 أكتوبر أدناه تتقدم عليها ضمن النطاق المحدد، ولا تحسم بقية القرارات المفتوحة تلقائيًا.

الطلب الجديد أجاز الانتقال إلى عميل Flutter إضافي على API الحالي، دون إلغاء قرار PWA الأولي أو إعادة تفسير تسليماته. أجاز أيضًا أدوارًا متعددة لهوية واحدة واختيار عضوية صريحًا. استُخدمت tokens opaque قصيرة وrefresh مدوّر مخزن hash على الخادم مع جلسة لكل جهاز؛ لا حاجة JWT أو identity server جديد. [الموافقة الإضافية](../requirements/NATIVE_MOBILE_AUTHORIZATION_2026-10-04.md) و[تفاصيل التنفيذ المرحلي](../mobile/MOBILE_ARCHITECTURE_v1.0.md). لا تُعد الموافقة حسمًا لأي قرار تجاري/غذائي/طبي مفتوح أو اكتمال التطبيق native.

## تصحيح المالك — 2026-10-08، CH-019..022

- OD-011 أصبح معتمدًا ضمن match يدوي فقط: بطولة وفريق منتخب مستقل عن مجموعة التدريب، موعد ومكان ومنافس ونتيجة، إشعار داخل التطبيق. تستعمل المباراة roster الفريق عند النشر ويمكن تمييز البدلاء؛ جمهور النشر snapshot لا يشمل من انضم لاحقًا تلقائيًا، ويعاد التحقق من ربط الولي/إسناد المدرب عند القراءة.
- رسم بطولة قيد مالي مستقل عن فترة التدريب؛ سعر وعملة snapshot، مفتاح idempotency، إثبات خاص، قبول/رفض ذري وإيصال مستقل. لا تكديس خصومات تدريب عليه ولا تمديد الاشتراك. لا fixture engine أو broker.
- مشغّل المنصة هو حساب فردي له منحة عالمية صريحة مخزنة بالخادم ومحدودة بإدارة الهوية البصرية. لا تمنح Owner هذه المنحة، ولا API يمنحها لنفسه. تجهيز حساب إنتاجي يحتاج إجراء تشغيل موثوق؛ حساب Demo منفصل وموسوم. لا منصة نشر جديدة.
- الاسم/ألوان hex وصورة logo محفوظة لكل tenant؛ upload صور PNG/JPEG/WebP فقط بحد حجم، دون SVG أو URL خارجي. لا استخراج palette يغير الشعار؛ ألوان المرجع الأحمر والأسود default للديمو، مع اختيار ألوان يدوي للمشغل. أيقونة iOS/Android مضمّنة وقت البناء ولا تتغير آليًا برفع tenant logo.
- سياسة حضور المدرب تضبطها الأكاديمية وتتحقق عند كل كتابة، ولا تعطل المواعيد والتقييمات. إعدادات التحويل للمالك أو إداري بمنحة مستقلة صريحة.
- التغذية تبقى معلومات عامة؛ بطاقة الرئيسية preview صغير بينما التفاصيل كاملة بصفحة المكتبة. لا إعادة تسمية «خطة علاجية» ولا اعتماد طبي.

## أيام التدريب والحصص — 2026-10-08، CH-023

تصحيح CH-024 اللاحق في [v1.7](../requirements/ACADEMY_REQUIREMENTS_BASELINE_AR_v1.7.md): الفترة الظاهرة الافتراضية يوم اليوم الفعلي في `Africa/Cairo`، يمرره Server Component إلى الواجهة بنفس القيمة لتجنب اختلاف hydration/UTC. المسح يعيد تاريخي اليوم؛ إفراغهما يعرض كامل التاريخ. هذا فلتر قراءة فقط ولا يغير ساعة أعمال Demo الثابتة أو ساعة الأمان أو جدول المجموعة.

المصدر [v1.6](../requirements/ACADEMY_REQUIREMENTS_BASELINE_AR_v1.6.md). يبدأ عرض الأسبوع بالسبت، لكن قيم `DayOfWeek` ثابتة: السبت `6` والأحد `0`، وليست index في قائمة العرض. `WeekdaysField` يرسل القيم نفسها ويستعيد enum/numeric؛ `TimeField` يعرض ساعة/دقيقة/صباحًا–مساءً ويرسل `HH:mm`، مع الاحتفاظ بالدقائق وعدم قبول وقت جزئي. لا تغيير لقاعدة بيانات أو مولد الحصص.

قائمة الحصص الإدارية تستعمل API داخل الأكاديمية يتطلب منح الهيكل والأشخاص وقراءة الحضور معًا؛ لا توسيع وصول المدرب/ولي الأمر. فلاتر الأشخاص تجمع الإسناد الحالي وسجل الحضور التاريخي؛ فلتر ولي الأمر اتحاد أبنائه المرتبطين، والفلاتر المختلفة تتقاطع. لا تتكرر الحصة المشتركة. الخيارات tenant-scoped، ولا contact data. تعرض الواجهة 50 صفًا بالصفحة من جميع الحصص غير الملغاة؛ server pagination عند الحاجة لاحقًا، بلا بنية جديدة الآن. نجاح الكتابة وحده يطلق إشعارًا عربيًا؛ النماذج المستقلة ترجع لقائمتها، لا تقطع إشعارات الحفظ خطوات wizard أو المعاملات المضمنة.

## توضيح المالك — 2026-10-08، CH-026..029

- حد الحضور هو اليوم الحقيقي في `Africa/Cairo`، لا 28 سبتمبر الثابت للديمو. تحقق الخادم يحمي اللاعبين/المدربين حتى عند تجاوز الواجهة. الحضور يبدأ باليوم؛ تقارير الفترة والحصص بأول الشهر إلى اليوم. المسح يزيل قيد التاريخ كليًا، ويتقدم على انتظار فترة جديدة في CH-025، مع بقاء العزل وحدود التصدير.
- حساب راتب الشهر الجزئي معتمد: `MonthlySalary × InclusiveContractDays / ActualCalendarDays`، ثم تقريب نهائي لمنزلتين. العامل بلا حساب ليس مستخدمًا مفترضًا. الراتب المستحق = الأساسي النسبي − الخصومات + الإضافات المعتمدة؛ المعلق/المرفوض لا يؤثر. الرواتب مستقلة عن تحصيل الأطفال وليست معالجة قانونية/ضريبية كاملة.
- سداد الشهر snapshot محفوظ، وتمنع الأقفال والمعرفات الفريدة التكرار وتغيير خصم/إضافة شهر مسدد. تعديلات الراتب/العقد اللاحقة لا تغيّر السداد القديم؛ الأشهر غير المسددة تستعمل بيانات الموظف الحالية، وسجل تعديلات رواتب تاريخي مستقل لم يُنفذ. المراجع المفوض لا يقبل طلبه الذاتي.
- المالك يقرأ/يدير الرواتب؛ الإداري يحتاج منحة صريحة، والمدرب يطلب لنفسه فقط. هذا ليس بديلًا لمصفوفة CRUD وتفويض الفروع؛ CH-028 ما زال ينتظر تنفيذ الخادم/الواجهة واختبارات الاستثناء المالي قبل الإعلان عن اكتماله.
- سبب إنشاء قاعدة عرض يصبح اختياريًا، مع بقاء سبب قيد خصم مالي مطلوبًا. CH-029 يجيز القيمة الثابتة والتجديد الجماعي لكنه لا يحولهما تلقائيًا إلى وظائف منفذة؛ الخطة والدليل في [سجل التنفيذ](../delivery/STAFF_ATTENDANCE_EXECUTION.md).
