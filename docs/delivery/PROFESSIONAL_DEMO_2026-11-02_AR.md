# Professional Academy — ديمو V5.22 وتجهيز VPS

المنتج المستقل Academy Management Platform / iAcademy One. لا وصول إلى مستودعات الأهلي أو قواعده أو أسراره، ولا تغيير لشغله. لا شراء أو نشر أو DNS أو مدفوعات أو بيانات عملاء.

## النسخة والبيانات

فرع `codex/vps-compose-readiness` و[PR1 مسودة إلى main](https://github.com/salah1seleem/academy-management-platform/pull/1). فحص التواريخ والأنساب أثبت أن فرع16 أقدم من تنفيذ15؛ حُفظت تعديلات المصدر حتى30أكتوبر ثم أضيفت شريحة V5.22 المعتمدة. نسخة حفظ خاصة خارج المستودع تسبق التعديل؛ لم تُرفع المراجع الخاصة أو البيانات أو الأسرار.

قاعدة `academy_professional_demo_20261102` محلية مستقلة، PostgreSQL17 على127.0.0.1:55471 وAPI على127.0.0.1:5396. داخل Professional:300 لاعب خيالي،150 ولي أمر،18 مجموعة، الرحاب ومدينتي والشروق؛165 كرة قدم و90 سباحة و45 كرة سلة. الأكاديمية الثانية ولاعبها الخيالي مخصصان لاختبار العزل. لا صور أطفال حقيقية في بيانات هذا الديمو أو حزمة Flutter الجديدة.

الموبايل أولًا: بانر للمالك، وشريط العمليات المتحرك قبل الاشتراكات. المدرب يفتح المجموعة ولاعبيها مباشرة، والتقييم الشهري ظاهر دون فتح حصة. الحضور يظهر فقط عند التفويض، والخادم يفرض الصلاحية والمجموعة مجددًا. تفاصيل المواعيد والتواصل اختيارية داخل المجموعة حتى تظهر قائمة اللاعبين مبكرًا. لا رفع وسائط حصة من مجموعة بلا جلسات فعلية.

## الدليل المنفذ

- Flutter:تحليل بلا ملاحظات،44 اختبارًا مستهدفًا نجحت؛ بعد تنقيح المجموعة أُعيدت اختبارات المدرب التسعة ونجحت جميعًا. يشمل ذلك360/390/430px والمظهرين وتكبير200%، والتقييم المستقل وحالتي تفويض الحضور.
- Native integration على محاكي Professional المستقل:نجحت الرحلة الفعلية الأولى في38ثانية بعد الاتصال المباشر بخدمة اختبار Dart. شراء طقم أحمر، إثبات تجريبي واضح، مراجعة المالك، خصم واحد، إعادة اعتماد دون خصم إضافي، حالةConfirmed للأسرة وتطابق زيادة تقرير المنتجات مع قيمة الطلب. قراءة قاعدة الديمو أكدت24→23 وطلبًا مؤكدًا واحدًا650جنيهًا. لا تحويل بنكي حقيقي؛ رفع الإثبات عبرAPI لا يثبت منتقي ملفات الجهاز.
- رفض فعلي404 للمالك وولي الأمر عند طلب لاعب الأكاديمية الثانية.
- فحص ملفات حزمة iOS:ست صور اصطناعية فقط؛ صفر ملفاتreference-child. إعادة seed لم تكرر اللاعبين أو التحصيلات. حواجز الإنتاج/اسم القاعدة/الخادم البعيد رُفضت تحتPython-O أيضًا.
- CI217 عند2f5b4392:Web870،Flutter1159،containers وe2e ناجحة؛ المتصفح120+54+2. فشلBackend:تكامل1198/1236،Unit317/318،Architecture1/1. اختلافPNG عولج ونجحتUnit318 محليًا؛ تجهيز مجموعات التواصل صار يشترط نشاط الفرع والرياضة. CI219 عندab90880e يعيد التحقق الكامل؛ لا اعتمادBackend نهائي قبل نتيجته.

إعادة الرحلة على أحدث تنقيح المجموعة وحفظ اللقطات والنسخة العادية قيد التحقق؛ نجاح الرحلة الأولى لا يعني تثبيت هذه النسخة العادية. تقارير runtime ولقطات التصوير تحتoutput وtmp مستبعدة منGit. تعطل تثبيت أحدث حزمة مرة بسبب امتلاء القرص؛ أُزيلت مخرجات بناء واعتماديات قابلة لإعادة التوليد فقط، مع حفظ الكود وقاعدة العرض والنسخة الخاصة. يُعادnpm ci عند تجهيز الويب المحلي.

## Docker والإنتاج

Compose يشغلAPI وNext.js وPostgreSQL17، معmigrator منفصل وصلاحياتCRUD للتشغيل، health checks، وسائط ومفاتيح دائمة وbackup/restore إلى هدف جديد. عامل الاستيراد داخلAPI. نجحت دورة Linux CI الفعلية للبناء و160migration وثبات الوسائط والمفاتيح وحظرOTP الإنتاجي والنسخ والاسترجاع المعزول. تعليمات VPS في[دليل النشر](../../infra/vps/DEPLOYMENT_AR.md)، ونتائج الجولات في[سجل التحقق](../../infra/vps/VALIDATION_AR.md).

OTP الإنتاجي يحتاج مزودًا حقيقيًا؛ يستجيب501 حاليًا، ورمزDemo لا يُفعّل لعملاء. التهيئة الآمنة لأول مالك/منصة وMFA والاسترداد،TLS والأصول وRPId الفعلية، قنوات الدفع والإشعارات المطلوبة، نسخ مشفرة خارج الخادم ومراقبة وتجربةstaging، ونجاح الفحوص المطلوبة موانع قبول إنتاج. يبقىPR مسودة دون دمج أو نشر.
