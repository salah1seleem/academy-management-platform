## عيوب التطبيق التي أصلحت فعليًا

1. مساحة الطفل في Guardian تتسع لتكبير النص200% دون overflow، مع مفاتيح مستقرة للتبديل بين خدمات الطفل المختار.
2. مربعا التاريخ يستخدمان Wrap بدل صف لا يتسع للنص المكبر. رأس المدرب يعرض اسمه الفعلي.
3. بطاقة المباراة تستعيد المشاركين/البدلاء والمدرب المؤكد والملاحظات؛ قائمة المالك على Web تبدأ بكل التواريخ مثل التطبيق، مع احترام الفترة الصريحة عند تمريرها.
4. التحصيل اليومي/الشهري في Home يفتح تقريره مباشرة. زر CSV يتجدد بعد تحميل التقويم، فيرسل الفترة المعروضة فعلًا ويحذف branchId الفارغ بدل إرسال Guid غير صالح. تفاصيل الإلغاء/الاسترداد لم تعد تختفي من القائمة.
5. الرجوع من القرارات يحدّث Home للهوية نفسها فقط؛ تحديثها بعد تسجيل الخروج لا يرسل طلبات مالك بهوية منتهية، وcallback الحالة لا يعيد Future.
6. أبقت صفحة الصلاحيات الواجهة البسيطة افتراضيًا، واستعادت خيارًا صريحًا للقوالب المتقدمة. حفظ صلاحيات سياق إضافي يرجع إلى سياقات الإداري الأصلي، لا يعامل السياق الجديد كموظف أصلي. لا توسيع تلقائي لمنح المدرب أو تجاوز أفعال الإداري الصريحة.
7. قُيد الحد الأدنى لعناصر Grid/carousels في Owner Web، وأُخفي drawer المغلق من التخطيط على الموبايل. الدليل قبل الإصلاح: Chromium Pixel7 بعرض412 كان يولد innerWidth598 وscrollX−186، فتزيح اللمسات إلى القائمة أو القسم الأب. تحقق الإغلاق يفحص عرض الجهاز نفسه ثم ينقر الرابط عادة، بلا force أو إخفاء عيب بواسطة scrollWidth≤innerWidth فقط.

## حفظ CSV داخل iOS فعليًا

من Main App العادي دخل المالك إلى التقارير المالية، اختار تصديرCSV، واستخدم حوار Files/Downloads وزر Save. الملف المحفوظ داخل حاوية File Provider للمحاكي قُرئ للتحقق:33سجلًا، صافي27930، مطابق للتقرير. لم تُرفع نسخة CSV أو بيانات جلسة. [صورة حوار النظام](evidence/mobile-refinement/csv-system-save-typical.jpg). التحقق اللاحق في Flutter يفحص نفس URI الذي أنشأه ExportButton، بما فيه from/to وعدم وجود branchId فارغ.
