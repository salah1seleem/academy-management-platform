## التنفيذ

- يفتح إشعار `AttendanceCorrection` طلبه المحدد في `/dashboard/attendance/corrections/[id]`؛ أضيف الرابط نفسه إلى قائمة الطلبات القائمة. الإشعار دون معرف محفوظ لا يُربط بالتخمين.
- الصفحة تقرأ المصدر المفرد من API القائم؛ تتحقق من تطابق المعرف، وتعرض السبب والمقدم والحالات السابقة والمقترحة والمراجع وملاحظة القرار ووقته، مع رابط كشف نفس الحصة.
- أزرار القرار مرتبطة بـ `canApprove` المحسوب خادميًا. الإداري يراجع طلبه دون اعتماد، والخادم يظل صاحب قرار الصلاحية وعزل الأكاديمية والعضوية والفرع. لم تُضف صلاحية للمدرب أو ولي الأمر.
- تُثبت نية القرار: نسخة الطلب والاعتماد/الرفض والملاحظة المنقحة. لا تُعلن نتيجة ناجحة قبل قراءة الحالة والملاحظة المحفوظتين ووقت التطبيق للاعتماد. أُلغي إعلان النجاح العام المبكر لهذا الإجراء.
- إذا نجح POST وفشلت قراءة النتيجة، يعيد زر التحقق GET فقط؛ إذا ضاعت استجابة POST يعاد نفس الجسم إلى الخدمة القائمة ذات إعادة القرار الآمنة. يمكن إعادة تحميل المصدر صراحة بعد رفض نسخة قديمة، دون إرسال قرار جديد.
- أضيف التحقق من المعرف والحالة ووقت التطبيق أيضًا إلى قرارات القائمة السابقة، دون إزالة إجراءاتها أو كشف الحصة.
