# 01/12 — تفويض شرح الصفحات وحياة المشغل

تحديث لاحق: قُبل تشغيل مقطع HTTPS فني فعلي وإيقافه وسحبه في13ث مع استعادة إعداد العرض؛ [الدليل الأحدث وحدوده](EVIDENCE_01_12_NETWORK_VIDEO_AR.md). عبارات عدم تشغيل مقطع في هذه الدفعة أدناه تصف تاريخها السابق؛ محتوى شرح الأكاديمية المعتمد نفسه لم يقدم.

23 أكتوبر 2026. استكمال المشغل القائم، لا تصميم أو خدمة فيديو جديدة. المرجع التجاري وتصميم Design-2 محفوظان، ولم تعدل المتطلبات أو الموافقة. الدفعة السابقة لملف الطفل تقدم مثبت؛ هذه الدفعة تغلق فجوة مختلفة في شرح الصفحات.

## الإصلاح

كان PageVideoPlayer يعيد فحص الرابط عند التهيئة فقط، ويحتفظ بعنوان لقطة التنقل بعد تغير السياق؛ الإيقاف في الخلفية وحده كان يسمح باستئناف مشغل قديم دون قراءة تفويض جديدة.

- هوية السياق تشمل الأكاديمية والعضوية والدور ونسخة التفويض. تغيرها يطمس العنوان والإطار ويفصل المشغل؛ الدخول اللاحق لنفس العضوية أو العودة لنفس النسخة لا يعيدان الصفحة القديمة.
- زر الشرح يرفض ردًا يخص دورًا أو صفحة أخرى، ويتجاهل الرد الذي عبر تغير السياق أو استبدال الوجهة، حتى لو عاد السياق إلى قيمه السابقة. الرسائل الظاهرة عربية.
- عنوان المشغل من القراءة المصرح بها الحالية، لا من بيانات التنقل القديمة. يجب أن يبقى الرابط هو المقصود وأن يكون HTTPS دون بيانات اعتماد مضمّنة.
- كل تشغيل يعيد قراءة المصدر قبل استدعاء play؛ الإيقاف لا يكرر الطلب. سحب الفيديو أو تغير رابطه يحرر المشغل ويعرض رسالة عدم التوفر.
- الخروج من المقدمة يحرر المشغل ويخفي العنوان والصورة؛ العودة تقرأ المصدر وتعيد التهيئة دون تشغيل تلقائي. الرد المتأخر لا يشغل مشغلًا فُصل أثناء الانتظار.
- لا API أو جدول أو migration أو تسعير أو تحصيل جديد. أضيف اعتماد اختبار مباشر لنفس `video_player_platform_interface 6.9.0` المثبت مسبقًا باستخدام pub get offline؛ لا ترقية للحزم أو طلب فيديو خارجي.

## الفشل الذي كُشف أثناء التحقق

فشلت خمس حالات في الدفعة الأولى عند انتظار تحرير منصة الفيديو واختبار إطار بعد توقف رسم الخلفية. أصلح الاختبار ليراقب حدث inactive الحقيقي عند مغادرة المقدمة، حيث ما زال رسم الإطار متاحًا، وليستخدم تدفق منصة مفتوحًا حتى التحرير كما يفعل التنفيذ المثبت، مع انتظار إتمام التحرير خارج fake-async؛ بقيت assertions الاختفاء ومنع play والتحرير نفسها. فشل وسيط كشف عدم تهيئة completer في fixture، ولم يحتسب نجاحًا.

بعد نجاح حالات المشغل، كشف الرجوع اختبارًا قديمًا يبحث عن تبويب «المزيد» لدى ولي الأمر، بينما التصميم المعتمد له أربعة تبويبات. أصبح اختبار التعريف يفتح شرح الصفحة من زر الرأس الفعلي؛ بقيت فحوص حفظ التخطي وعدم إعادة onboarding والرد المتأخر. حُدثت fixtures القديمة للدور والصفحة كما يعيدهما API بالفعل، دون تخفيف الرفض عند اختلافهما.
