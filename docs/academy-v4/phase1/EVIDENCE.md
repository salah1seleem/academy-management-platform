# دليل Phase 1 — نتائج الخلفية المحددة

التاريخ: 21 أكتوبر 2026. المستودع القائم `.NET 10 / EF Core / PostgreSQL / Next.js / Flutter`. فرع البداية `codex/15-native-mobile-app`، الرأس `7e05d60`، وشجرة البداية نظيفة.

المرحلة مصرح بها مباشرة في المحادثة. بطاقة النطاق: Phase 1 / الشريحتان 24 و25 والانحدار وتجهيز التصميم. سياسة المشروع توصي Sol/High للأموال والصلاحيات؛ لم تُغيّر إعدادات المستخدم أو يُدّع استهلاك أو تكلفة مقاسة. لم تُستخدم subagents أو خدمات جديدة.

## حدود البيئة والدليل

- ثلاث قواعد محلية أنشئت خصيصًا لهذه المرحلة: `academy_phase1_isolated_20261021` للتطوير والاختبارات الأولى، و`academy_phase1_final_20261021` للجولة الأوسع الموقوفة، و`academy_phase1_acceptance_20261021` للقبول المحدد. طُبقت 141 migration من الصفر على قاعدة القبول. لا قراءة أو تعديل لقاعدة عميل أو إنتاج أو قاعدة العرض القائمة.
- أُنشئت migration `20261021113858_Phase1ConnectedImports`: ResultSummary في الدفعة، وTournamentRegistration مستقل عن المال، بمفاتيح أكاديمية مركبة وفهرس فريد وحارس توافق الرياضة/الفرع/العمر وثبات المصدر. تطبيق جميع migrations على القاعدة النهائية نجح.
- الـAPI لا يطبق migrations تلقائيًا؛ فشل التشغيل الأول على القاعدة الفارغة قبل تطبيقها، ثم عولج الإعداد صراحة. لا ننسب هذا الفشل لمنطق المنتج ولا نحذفه من سجل العمل.
- سبقت القبول جولة موجهة 18/18 ناجحة؛ نتائج النسخة النهائية المحددة أدناه تشمل الإضافات اللاحقة ولا تُجمع مع الجولة السابقة بوصفها اختبارات مستقلة.
- لا تعديل نهائي لـFlutter/Next أو UI أو نشر أو رسالة خارجية. إثبات API برمز موبايل لا يثبت رحلة Flutter مرئية. لا لقطة مطابقة تصميم مدعاة.

## العيوب التي ثبتت وأُصلحت داخل النطاق

1. القالب القديم يستخدم GUIDs ومراجع مجهزة مسبقًا؛ أُضيف عقد عربي بأكواد مقروءة يحول لنفس validator/queue/publisher بدل محرك استيراد ثانٍ. بقي القالب القديم ونشره مدعومين.
2. اصطدام أسماء المراجع الفريدة كان يصل للنشر؛ المعاينة تعيد السجل المطابق وتمنع المختلف برسالة صفية، بلا overwrite.
3. المقارنة النصية لـdecimal snapshots ميّزت `1000` عن `1000.00` عند إعادة الرفع؛ طُبّعت الدقة قبل مقارنة التعريفات، دون تقريب الأرصدة المالية المستوردة.
4. الإعفاء الجديد احتاج نفس JSON enum/source contract القائم في FreeTraining؛ استُخرج بناء المصدر والفترة المشترك وأعيد استخدامه بدل إعادة كتابة مسار إعفاء آخر.
5. إنشاء الحصص كان يملك معاملة منفصلة؛ المولد ينضم الآن إلى معاملة المستدعي عند وجودها، مع تقييد مجموعات الاستيراد فقط. فشل مرحلة لاحقة يعيد الهيكل والهويات والتسجيلات والعلاقات والحصص كاملة.
6. صلاحية CRUD عامة لا تكفي لمنح استثناء؛ أضيف leaf صريح، وتحقيقه تحت قفل المنح، وتأكيد استبدال العرض، وحفظ التدقيق والسعر والعملة في المصادر القائمة. التكرار يعيد العملية بدل تطبيق خصم آخر.
7. قارئ XLSX مستقل أظهر الخلايا الفارغة المصدّرة كفهرس shared string؛ أصبح الكاتب يصدرها sparse بلا عنصر قيمة، ثم أعيدت الوحدة 288/288 والتكامل المتأثر 27/27 وقراءة الملف الفعلي.
8. الخاص/شبه الخاص لا ينشئان حجز مورد مبهمًا: يلزم سجل مجموعة قائم معتمد؛ تحقق التسكين المشترك يراجع الحصص والمورد والمدرب والمستوى والسعة داخل النشر. الفترة التاريخية ليست تحصيلًا أو إثبات حضور حاليًا.

### المحاولات غير الناجحة وحدودها

- فشلت محاولات مبكرة في مقارنة decimal وإعداد fixture وJSON enum لعقد الإعفاء؛ أصلحت ثم اجتازت القبول المحدد. لا تدّعي هذه الوثيقة أن المحاولة الأولى نجحت.
- بدأت جولة أوسع من440 حالة؛ أُوقفت بعد نحو24د دون اكتمال، **وليست Passed**. أظهر sampling/managed stack الوقت داخل ASP.NET RequestDelegateFactory/LambdaCompiler لتكرار بناء hosts الاختبارية، ولم تظهر أقفال SQL نشطة تفسرها. جولة104 المحددة اكتملت فعلًا. لم يُعدّل timeout أو إطار المنتج لتجميل النتيجة.
- أول فحص EF دون متغير الاتصال رفض الإنشاء وفق تصميم المشروع؛ إعادة الفحص بالاتصال المحلي الصريح أعادت «No changes have been made to the model since the last migration».
- رُسمت32 منطقة من الأوراق، ورُوجعت لوحتا الاتصال وصورة الأعضاء كاملة للمنطقة المعروضة. عارض artifact PNG لم يعكس ترتيب الأعمدة RTL وأسقط صفر الهاتف بصريًا رغم أن قيمته وصيغته النصية وXML RTL صحيحة بقراءتين مستقلتين. هذه **محدودية في دليل العرض**؛ لم يُختبر Microsoft Excel نفسه ولم تُدّع مطابقة بصرية كاملة. الملفان المسلمان هما bytes التنزيل الأصلي بالـhash في [workbooks.json](evidence/workbooks.json)، لا إعادة تصدير من العارض.

## إعادة التحقق

استعمل قاعدة اختبار **جديدة** من إنشائك، ولا تحمل `.env` أو أسرار الإنتاج. اسم PostgreSQL أدناه محلي ويستبدل بهوية اختبار مناسبة. عند تكرار التشغيل على نفس القاعدة، دفعات الاختبارات مستقلة والمثال ثابت يعاد استخدامه؛ لا reset لقاعدة موجودة.

```sh
createdb academy_phase1_acceptance_20261021
ConnectionStrings__Default='Host=localhost;Database=academy_phase1_acceptance_20261021;Username=omar' dotnet ef database update --project apps/api/src/Academy.Infrastructure --startup-project apps/api/src/Academy.Api
```

شغّل `dotnet test tests/integration/Academy.IntegrationTests` مع `ACADEMY_TEST_CONNECTION_STRING` لنفس الاتصال و`--filter` بقيمة [acceptance.filter](acceptance.filter) كاملة، ثم:

```sh
ACADEMY_TEST_CONNECTION_STRING='Host=localhost;Database=academy_phase1_acceptance_20261021;Username=omar' dotnet test tests/integration/Academy.IntegrationTests --filter 'FullyQualifiedName~Phase1_connected|FullyQualifiedName~Phase1_actual_downloaded|FullyQualifiedName~.IMP_'
dotnet test tests/unit/Academy.UnitTests
dotnet test tests/architecture/Academy.ArchitectureTests
ConnectionStrings__Default='Host=localhost;Database=academy_phase1_acceptance_20261021;Username=omar' dotnet ef migrations has-pending-model-changes --project apps/api/src/Academy.Infrastructure --startup-project apps/api/src/Academy.Api
```

أسماء الحالات وتوقيتها كافية لتمييز النتيجة عند تغير عدد اختبارات المستودع لاحقًا. خطوات العرض حسب الدور في [DEMO_AR](DEMO_AR.md). القالبان داخل [examples](examples/README_AR.md) مرتبطان بسياق Demo؛ Download API يولد نسخة للأكاديمية الموثوقة الحالية.
