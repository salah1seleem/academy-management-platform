# تحديث المتطلبات v1.8 — اختيار الأيام وفلاتر الفترة

التاريخ: 8 أكتوبر 2026. المصدر: تصحيح المالك المباشر، إضافة إلى v1.0–v1.7 دون تعديلها أو سجل الموافقة الأصلي.

## CH-025 — أيام مدمجة وفترة شهرية قابلة للمسح

- يعود اختيار أيام إنشاء/تعديل جدول المجموعة إلى بلاطات صغيرة تبدأ بالسبت، ويتغير لون اليوم المحدد بوضوح. لا تعرض مربعات اختيار كبيرة. تبقى قيم الأيام الفعلية والحفظ واستعادة الاختيار كما هي.
- كل فلاتر الفترة في Dashboard تبدأ من أول الشهر الحالي إلى اليوم الحقيقي في `Africa/Cairo`، لا تاريخ Demo المرجعي. الفترة الصريحة القادمة من رابط تقرير تُحفظ بدل استبدالها بالافتراضي. يشمل ذلك الحصص والرئيسية والمالية والحضور وطلبات الدفع والمباريات والسجلات الطبية وقائمة طلبات التسجيل القديمة.
- «مسح» يفرغ التاريخين وبقية الفلاتر، ولا يعيد ملء الافتراضي برد API أو إعادة عرض المكوّن. يختار المستخدم الفترة الجديدة بنفسه. لا يغيّر ذلك تواريخ إنشاء السجلات أو تاريخ الميلاد أو حدود جدول المجموعة.
- لا توسعة لقواعد الخادم: التقارير والمؤشرات وطلبات الدفع وقائمة الحضور ذات الفترة المحدودة تنتظر اختيار تاريخين قبل القراءة/التصدير؛ القوائم التي تدعم غياب الفترة أصلًا (الحصص والمباريات والطبية وطلبات التسجيل القديمة) تعمل بلا قيد تاريخ بعد المسح.

هذا التصحيح يحل محل الافتراضي ومسح الفلاتر في CH-024، وليس تغييرًا لساعة الأعمال أو بيانات Demo أو الصلاحيات.
