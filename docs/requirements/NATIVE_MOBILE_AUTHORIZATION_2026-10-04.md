# إضافة النطاق المعتمدة: برنامج Native Mobile

المصدر: طلب المستخدم «Native Mobile App Program» المرفق في هذه المهمة، وتصحيحه المباشر للصور والوجبات. تاريخ التسجيل: 2026-10-04. هذا ملحق تنفيذ، ولا يستبدل baseline v1.0 أو سجل موافقته أو يختلق AC/OD IDs.

- أُجيز تطبيق Flutter أصلي واحد لـGuardian/Coach/Owner، إضافةً إلى الويب الحالي وعلى API نفسه، مع تسجيل هاتف/OTP وجلسات أجهزة قابلة للإلغاء واختيار صريح للدور/الأكاديمية عند تعدد العضويات.
- أُجيز دعم أدوار متعددة للهوية نفسها داخل الأكاديمية. تظل صلاحيات المورد والوصاية والإسناد منفصلة؛ لا يجمع الطلب صلاحيات الأدوار.
- أُجيز Demo عرض نظيف لكرة القدم: ثلاثة فروع وأربعة مدربين ونحو ثلاثين لاعبًا، مع reset مقيد آمن وفصل fixtures الاختبار متعدد الرياضات. لم يُنفذ ذلك بمجرد تسجيل الموافقة.
- صور المحادثة هي مرجع Guardian المرئي. الصورة لا تعيد إدخال مخطط الملعب أو AI Reports أو الدورات المكثفة أو تجارة التغذية. لا تُنسخ شعارات الأهلي أو صور الأطفال في المرجع.
- طلب المستخدم صراحةً وجبات مختلفة مناسبة للأطفال، **بلا شكشوكة أو كشري**. الحفاظ على شبكة الصور والتبويبات والتفاصيل، لكن دون أسعار أو نجوم أو كمية أو شراء. مصدر القيم وحجم الحصة وحالة المراجعة لازمة؛ التوصيات معلومات عامة لا تشخيص ولا وصفة فردية ولا هدف سعرات لطفل.
- أُجيز Create Coach في الويب، وإعادة استخدام التدفقات المالية والتقييم والحضور القائمة في Flutter، وتوثيق واختبار كل مرحلة وcommit/push مرحلي إلى `codex/15-native-mobile-app` دون main.

الموافقة على التنفيذ لا تعني جاهزية SMS أو payment provider أو توقيع المتاجر أو production media؛ ولا تعتمد تلقائيًا صيغة التقييم أو قرارات التجارة المفتوحة. التنفيذ الفعلي موثق في [STATUS](../delivery/STATUS.md) ومعمارية [الموبايل](../mobile/MOBILE_ARCHITECTURE_v1.0.md).
