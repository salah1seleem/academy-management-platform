# تشغيل فحص وسائط الأطفال — V2-15A3b / D3-070

## تحديث V2-15A3c / D3-071 — الاحتفاظ والحذف والحصص

هذا القسم يضيف دورة حياة **Media في معرض التدريب فقط**. تظل بقية وثيقة15A3b وصفًا تاريخيًا للفحص وحده؛ عبارة «لم ينفذ الاحتفاظ بعد» أدناه تخص تلك الشريحة. لا سياسة حذف/حصة جديدة لـPhoto أوProof أوNews أوCampaign أوHelp، ولا مسح ملفات قديمة تلقائيًا أو إعادة نسب موافقات لها.

### الإعداد والقراءة

- المالك الكامل، لا مجرد صاحب زر إعدادات، يختار من صفحة إعدادات الأكاديمية مدة1–3650 يومًا للرفع القادم، والحذف بعد الانتهاء checkbox مستقل. تحفظ كمسودة ثم تحقق وتجهيز واعتماد تفعيل عبر المسار القائم. null يبقي الرفع القادم بلا موعد آلي. لا تعديل baseline/approval، ولا تاريخ رجعي أو تمديد/إحياء نسخة سابقة.
- رفع Media يأخذ snapshot من **الإصدار الساري المعاد قراءته تحت قفل config** بعد المعالجة، ويعيد فحص media entitlement. الحصة تقفل علىAcademy قبل حفظ الملف. RetainUntilUtc وDeleteOnExpiry ضمن مصدر النشر المحفوظ، لا يحسبان لاحقًا من إعداد متغير. الوقت فعلي UTC، وليس مرجع Demo.
- عند الوصول إلى الموعد، يحجب التنزيل ومعرض الأسرة/المدرب حتى لو لم يعمل التنظيف. الإدارة ترى metadata وحالة الانتهاء، لا bytes. الحذف اليدوي أيضًا يحجب الجميع فور حفظ الطلب؛ لا «أصل للإدارة» بعد الحذف كما في سحب النشر فقط. البيانات التاريخية على الكارت تسمى موعد احتفاظ مسجلًا، لا وعدًا بأن المحذوف ما زال متاحًا.
- السياسة والحدود في لوحة صغيرة مطوية داخل المعرض والرفع، وتقرأ من الخادم. إجمالي التخزين يظهر للمالك الكامل فقط؛ غيره لا يحصل على إجمالي فروع لا يملكها. Native يعرض السياسة والحالة والحذف، وليس محرر إصدارات إعدادات Native جديدًا.

### حذف آمن وموثق

- `POST /api/v1/assets/{id}/delete`، RequestId وملاحظة **اختيارية** حتى500 حرف. media Read+Delete ونطاق حي، لا Add/Edit وحدهما أوCoach/Guardian. reauthorization قبل replay؛ تغيّر النية بنفس المفتاح409. لا يحذف Photo أوProof أوأي purpose آخر.
- يحفظ PrivateMediaErasure أولًا، ثم يحاول إزالة الملف. تأكيد filesystem محفوظ في PrivateMediaPurge؛ لا يدعي atomic transaction بين القرص وDB. انقطع بعد unlink وقبل حفظ التأكيد؟ الطلب محجوب أصلًا، وإعادة المحاولة تكتشف غياب الملف وتكمل مرة واحدة. unique/FK/EF/SQL تحفظ الوقائع والمصدر والأكاديمية. لا حذف لـPrivateAsset/الجمهور/الموافقات أو استرجاع موضعي.
- StorageName يجب أن يكونGUID32 فقط، ولا recursive delete. إذا وجدت أي إشارة أخرى للاسم نفسه، حتى بأكاديمية أخرى، لا يزيله ولا يحرر الحصة. لا تبين للعميل مسارًا أو هوية مرجع آخر. خطأ الوصول/القرص يبقى pending؛ يمكن لصاحب الطلب إعادة نفس الإجراء بعد معالجة العائق، أو يعيده العامل عند تشغيله. لا تتجاوز صلاحية المصدر/التذكرة لحل عائق تخزين.
- مساحة الحصة **منطقية من مصادر الملفات**، وليست قياس المساحة الحرة على القرص؛ تحرر بعد unlink وتأكيد DB. قد يحتفظ نظام التشغيل بblocks لstream مفتوح، وقد يستمر تنزيل بدأ بتفويض صحيح قبل الحذف. لا استرجاع تنزيل سابق أو محو backup فوري. فتح stream داخل الطلب مع معالجة فقدان الملف يقلل نافذة404/500 عند تزامن المسح؛ لا ادعاء إيقاف كلstream بدأ سابقًا.

### الحدود والعامل

- `Media__StorageLimitBytes`: افتراضي1073741824 (1GiB) لكلAcademy، يحده الخادم إلى1..100GiB، لا يأتي من العميل. مجموع Media لكلAcademy يشمل الفروع كلها والملفات المسحوبة والمنتهية والمعطلة والـlegacy غير المزالة، لا عداد شاشة مفلترة. تُرفض إضافة جديدة409 عند الامتلاء، ولا تحذف بيانات لتخفيض الاستعمال. downgrade لا يمس التاريخ.
- `Media__DailyDownloadLimitBytes`: افتراضي536870912 (512MiB) لكلUser+Academy+يومUTC، حد تشغيلي قابل لضبط المشغل1..10GiB. كل GET يقدمbytes، بما فيهRange، يحجز حجم الملف كاملًا؛ حجز ذري عبر كل الجلسات. قد يستهلك الطلب مساحة الحجز حتى لو انقطع/لم يكتمل النقل، ولا يقاس byte network حقيقي. طلب دخول302 ورفض التفويض/تذكرة غير صالحة لا يحجزان. عند الامتلاء429؛ لا يؤثر على الاشتراك أو الراتب/التحصيل أو صلاحية الأسرة الأصلية، ويتجدد المفتاح في اليومUTC التالي.
- `Media__LifecycleWorkerEnabled=true` يشغل العامل في API الحالي، افتراضيهfalse. الدورة عند البداية ثمكلدقيقة، batch25 للمنتهي المختار صراحة و25للإزالةالمعلقة، معأقفالنفسالمصدر/التخزين. العامل لا يزورdirectory عامة أو يحذفorphan/`.processing` مجهولًا. ميزاتالتخزينالإنتاجي/backup/صلاحياتالمجلد/تنبيهالمشغل وfairnessعندكثرةطلباتمعطوبة تحتاجمراجعةالإصدار؛ لا ضمانdrainزمني أوGCبعدpowerloss هنا.
- تنظف فقط سجلات حجز التنزيل الأقدم من32 يومًا؛ ليس سجل النشر/الإزالة أو أي مال. لا إرسال/دفع/شراء/بلاغ حقيقي. شغّل migrations قبل API الجديد. migration126 تراكمية، defaultfalse/null للقديم. Down يرفض إذا وجد snapshot/قرار حذف؛ لا rollback لتاريخ قائم عبر إسقاط الأعمدة.

الحدود السابقة للفحص50MiB/8MiB تبقى؛ HTTP/proxy/filesystem limits تحتاج مراجعة تشغيلية فيH، ولم يختبر ملف50MiB كاملًا أو قياس أداء/virus scanner بهذه الشريحة. المعرض ليس نظام نسخ احتياطي أو إثبات محو قانوني.

## الاعتمادات

API يحتاج FFmpeg وFFprobe محليين محدثين على خادم API، لا داخل Flutter أو المتصفح. يستخدم الملف التنفيذي عبر ArgumentList بلا shell؛ لا NuGet/image service أو خدمة مدفوعة. الموجود على جهاز QA هو FFmpeg9.0.2 من Homebrew. CI يثبت حزمة ffmpeg من Ubuntu في backend وE2E؛ نجاح CI الجديد يجب فحصه، ولا نفترض تطابق بناء Ubuntu مع Mac.

المساران الافتراضيان `ffmpeg` و`ffprobe` من PATH. يمكن للمشغل ضبط `Media__FFmpegPath` و`Media__FFprobePath` بمسارات تنفيذية موثوقة، وليسا حقلي عميل/tenant. `Media__PrivateRoot` هو التخزين الخاص القائم، خارج أي web root. عملية الأداة لا ترث متغيرات بيئة API أو أسراره. أول فحص يتحقق من توفر probe ومشفّرات png/libx264/aac؛ فشل الاعتماد لا يحفظ الأصل كبديل. لا تنزيل أدوات تلقائيًا من طلب مستخدم.

هذه الأدوات **غير مرفقة في المستودع أو تطبيق الموبايل**. [ترخيص FFmpeg الرسمي](https://ffmpeg.org/legal.html) يعتمد على مكونات البناء؛ بناء الجهاز الحالي يتضمن GPL/libx264. لا ندعي أنه LGPL فقط أو أن توزيع صورة تشغيل/ثنائيات مستقبلية معفى من التزامات الترخيص/البراءات. راجع البناء والإشعارات ومصدره عند إعداد artifact التوزيع؛ لم ننشر Production أو نشتر ترخيصًا. [توثيق FFmpeg](https://ffmpeg.org/ffmpeg.html) مرجع الخيارات، وليس إثبات نجاح اختباراتنا.

## عقد الرفع والحفظ

- المصادقة وAcademy وصلاحية الهدف أولًا. Media تعيد التحقق الحي والمنح/الموافقات/الجمهور/الحصة تحت الأقفال **بعد** فك الترميز، فلا تحجز أقفال التشغيل طوال معالجة الفيديو. لا تضيف هذه المعالجة موافقة أو إذنًا للمدرب.
- التوقيع والنوع المعلن والحجم ما زالت مطلوبة، ثم فحص format/codec/dimensions/duration وأخيرًا فك وترميز فعلي للـpixels/samples؛ لا يكفي ftyp أو PNG header.
- JPEG/PNG/WebP → صورة PNG ثابتة. حد الإدخال/الناتج8MiB، بُعد≤8192، مجموع≤20مليون بكسل. قد يرفض JPEG صغير إذا كان PNG الناتج أكبر من الحد؛ لا يحفظ الأصل بدلاً منه. الألوان/الملف المضغوط قد يختلفان، ولا نحفظ EXIF/XMP/نص الكاميرا/geotags. لا وعد بالحفاظ على ملفات تعريف الألوان أو الصور المتحركة؛ المطلوب صورة ثابتة.
- MP4/MOV → MP4/H264، الصوت الأول إن وجد إلى AAC/stereo128k. الحد50MiB للإدخال والناتج؛120ثانية، ≤1920 لكل بُعد و≤2073600بكسل، معدل إدخال≤60fps، الناتج30fps. يرفض تجاوز/نقص مدة الناتج بأكثر0.25ثانية بدل قبول قص صامت. codecs الإدخال h264/hevc/mpeg4/mjpeg/av1/vp9، وليس أي codec داخل حاوية مزعومة. قد تتغير الجودة والحجم.
- لا نسخ metadata/chapter/subtitle/data أو مسارات إضافية؛ video/audio المحددان يعاد ترميزهما. geotags التي كانت metadata لا تنتقل. **لا يمكن بذلك إخفاء عنوان أو وجه أو موقع ظاهر داخل البكسلات أو الكلام نفسه**؛ مراجعة الناشر وقص/طمس خارجي عند الحاجة ما زالت واجبة. رفض ملف تالف/متنكر/ملحق غير قابل للفك ليس استثناءً يُتجاوز.
- مسارات عشوائية في `.processing` الخاصة، ومجلد عمل0700 على Unix، دون استخدام الاسم الأصلي. تُحذف ملفات العمل عند النجاح والفشل/إلغاء الطلب الطبيعي، ويُنقل **الناتج فقط** إلى StorageName القائم، وتُحفظ ContentType وLength للناتج. فشل DB يحذف الناتج المتولد. قتل النظام/انقطاع الطاقة قد يترك staging؛ لا ندعي garbage collector أو سياسة احتفاظ منشورة قبل تنفيذ الشريحة التالية.
- حد متزامن **عمليتان لكل process**، والزيادة503 دون طابور. مهلة كلية50ثانية تشمل الأدوات، probe5ثوان لكل مرة وencode40ثانية، threads1 وحد تخصيص64MiB لكل تخصيص للأداة، وstdout/stderr محدودان16KiB. هذه ليست حصة tenant أو حد RSS شامل أو sandbox لحماية نظام التشغيل.
- protocol=file فقط، demuxer محدد من التوقيع، وMOV drefs/absolute aliases معطلة صراحة. لا روابط شبكة أو playlist مقبول. الملفات التنفيذية تحتاج تحديثات أمن وتشغيل مستخدم محدود/عزل نظام مناسب في بيئة الإصدار. هذه **إعادة بناء محتوى وليست شهادة antivirus أو انعدام ثغرات**؛ لا ماسح فيروسات خارجي أو مراجعة قانونية/بشرية آلية مدعيان.

## الإخفاق والاستهلاك

400: ملف لا يستوفي الفحص/الحدود؛503: الأداة غير متاحة أو الفحص مشغول/انتهت مهلته. الرسائل عربية ولا تحتوي stderr أو مسار التخزين. إلغاء العميل يوقف process tree ويزيل عمله. Native ينتظر الرفع60ثانية ويعرض إخفاقًا بلا replay تلقائي. الرفع نفسه ليس idempotent: لو ضاع الرد بعد commit، راجع المعرض قبل إعادة الرفع.

URLs والـgallery كما هما؛ Native/Web يعرضان ContentType للناتج. روابط Media ذات120ثانية والتحقق الحي/الموافقات والسحب تبقى مفروضة. التنظيف هنا لملفات العمل الجديدة، **ليس حذفًا تاريخيًا أو سياسة احتفاظ أو storage/download quota**. لا تدوير ملفات قديمة أو حذف تاريخ نشر أو مال/حضور/رسائل. هذه البنود والتشغيل الإنتاجي والجهاز المادي وAndroid والبوابة H تبقى مفتوحة حتى تحققها المنفصل.
