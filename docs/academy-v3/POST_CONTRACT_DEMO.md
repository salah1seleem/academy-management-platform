# عرض عمولة بعد انتهاء عقد — C2C3E3a

إضافة اختيارية إلى Football Demo الموجود، لا reset أو تغيير لبيانات مجهولة. يلزم `ASPNETCORE_ENVIRONMENT=Demo` و`Demo__SeedEnabled=true` و`Demo__SeedProfile=Football` مع إعدادات OTP والدفع الداخلي التجريبية السابقة، ثم `Demo__PostContractPrivateSeedEnabled=true`. لا تفعّل في Production. اختبارات المتصفح تفعّلها على قواعدها المعزولة فقط؛ .env المحلي لم يُعدّل.

ينشئ المصدر مرة واحدة مدرب «مدرب عقد منتهٍ — عرض اصطناعي»، عقده ينتهي آخر الشهر السابق لأول تهيئة فعلية بتوقيت الأكاديمية. IDs ثابتة وتكرار التهيئة لا يغير تاريخ العقد أو قرار المالك ولا يسجل صرفًا. باقة8/2000 وحصتان قديمتان ونسبة40% وتحصيل InternalTest1000 مخصص تنتج50 مستوفية لكل حصة؛ الاعتماد لا يحدث تلقائيًا. لا تحويل أو رسالة حقيقية.

1. ادخل كمالك العرض `owner.football@example.test` بكلمة Demo المحلية. افتح ملف المدرب المذكور ثم «تنفيذ الخاص وعمولاته».
2. «مراجعة الاستحقاق» لحصة، ثم «حفظ استثناء للمراجعة». لا حركة راتب أو صرف للمراجعة.
3. افتحها مجددًا، اختر «معاينة مستحق نهاية العقد» ثم «تأكيد اعتماد العمولة دون صرف». المبلغ50 محسوب خادميًا وغير قابل للتحرير.
4. افتح حساب الموظف:50 معتمد،0 مسدد،50 متبقٍ، ولا كشف راتب جديد. تظهر العمولة ضمن backlog الرئيسية برابط الحساب حسب الفرع والعملة، مستقلة عن شهر الرسم.
5. راجع صرف20 ثم أكده؛ الحساب/CSV/الرئيسية تظهر المتبقي30. التسجيل توثيق لصرف تجريبي، لا ينفذ تحويلًا. السلف غير المخصصة لا تقاص تلقائيًا، وتخصيصها لهذا المصدر غير منفذ بعد.
6. قراءة المدرب من التطبيق الحالي: الهاتف الاصطناعي `+201099900980` وOTP الديمو المكوّن246810. صفحة مستحقاته تعرض المصدر/الصرف/المتبقي فقط، دون أدوات اعتماد/صرف أو ملاحظات داخلية. ليس هذا دليل اختبار Simulator أو جهاز فعلي في هذه الشريحة.

الرحلة المنفذة بقيت في `academy_v3_postcontract_e2e_final_20261015` على PostgreSQL المحلي المؤقت5433؛ هذه قاعدة اختبارات لا قاعدة العرض اليدوي. تشغيلها يحتاج API/Web على هذا المصدر صراحة، ولا ننقل بياناتها إلى قاعدة العرض أو ندعي أن خدمات المراجعة اليدوية حُدّثت. الصور والأدلة في [PROGRESS](PROGRESS.md). إعادة السيناريو من البداية تكون بقاعدة اختبار جديدة، لا بحذف قاعدة مجهولة أو تخفيف منع التكرار/OTP.
