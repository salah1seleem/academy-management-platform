# ظهور التبويب المختار في تنقل الإعدادات

بطاقة NAV-20261118. التوصية GPT-6 Sol / Medium لتعديل تنقل مشترك محدود مع تحقق متصفح فعلي. لا تغيير لإعدادات الموديل أو تكلفة مفترضة. النطاق إبقاء التبويب المختار ظاهرًا عند فتح الرابط وتغيير العرض والتنقل، مع حفظ الفلاتر والتركيز وسلوك المحتوى. لا تعديل للمتطلبات أو إقفال للشاشات التي تستخدم المكوّن بمجرد نجاحه.

## المراجعة البصرية قبل التنفيذ

روجعت لقطة 320 بكسل من قبول GitHub على f57b24bb. محتوى المالية ظاهر، لكن اسم «المالية والتحصيل» مقصوص عند طرف شريط التبويبات. شريط RTL أفقي قابل للتمرير، ويبدأ عند اليمين حتى مع tab=finance. الرابط يحدد التبويب الصحيح، لكن موضع التمرير لا يتبعه. [الصورة قبل التعديل](../../../tmp/qa-20261117/transfer-settings/cloud-payments/transfer-settings-recovery-fd510--after-validation-rejection-mobile-chromium/transfer-settings-320.png).

قرار الواجهة هو تحريك شريط التبويبات أفقيًا بالقدر اللازم لإظهار المختار بالكامل، دون تغيير الألوان أو الخط أو ترتيب الأقسام ودون تمرير النافذة رأسيًا. يبقى التمرير اليدوي متاحًا لرؤية بقية الأقسام. مصدر الاختيار query.tab، وقائمة التبويبات المتاحة مشتقة من بيانات الشاشة وصلاحيات الخادم. لا تعديل مالي أو إذن خادم من التنقل.

## التنفيذ والنتائج

الحالات مكتوبة. تُسجّل النتائج الفعلية حسب طبقة التحقق بعد التنفيذ. اختبارات الخادم والمتصفح العامة من الجولة السابقة ما زالت قيد المتابعة بمقابضها الأصلية، ولم يُعتبر انتظارها فشلًا أو سببًا لإعادة تشغيلها.

يستخدم التنفيذ قياس حدود الزر المختار وشريطه وتمرير الشريط وحده أفقيًا، مع ResizeObserver للشريط والزر لمراجعة تغيّر العرض والخط. لا مستمع لتمرير المستخدم يعكس اختياره اليدوي. نجحت ستة اختبارات محلية للتبويبات والإعدادات، تشمل بقاء النماذج المركبة ومحتوى القسم المخفي والقائمة التي تصل متأخرة والفلاتر وRTL. لا يُعد JSDOM دليلًا على هندسة التمرير؛ لهذا أضيفت أربع رحلات Chromium فعلية إلى مجموعة التشغيل في Core Browser QA.

أضيف Web QA لتشغيل فحوص الويب كاملة وبنائه على Ubuntu مستضافًا عند دفع فرع صريح codex/qa-web-*. تستثني CI العامة هذا النمط من push فقط؛ يظل main وطلبات الدمج والفروع الأخرى على الفحوص العامة، ويستمر تشغيل Core Browser QA يدويًا لكل شريحة. يمنع ذلك إعادة اختبارات .NET وFlutter غير المتغيرة عند كل إصلاح ويب. لا ينفذ النشر أو يستخدم قاعدة Staging.
