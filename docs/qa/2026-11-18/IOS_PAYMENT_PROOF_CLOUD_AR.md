# إثبات دفع الاشتراك الجديد — تطبيق iOS مثبت على GitHub

حالة البداية: حالات مكتوبة قبل التنفيذ؛ لم يبدأ اختبار المحاكي بعد.
المهمة IOS-PROOF-01؛ الموديل الموصى به GPT-6 Sol / High لحساسية الهوية والأثر المالي. لا تغيير لإعدادات المستخدم ولا ادعاء تكلفة مقاسة. النطاق: قراءة طلب قائم وصورته، التعافي، إيماءات الصورة، عزل الدور وتغيير سياق الأكاديمية. لا إقفال لإنشاء الاشتراك من الواجهة أو قبول الدفع أو التطبيق كله.

## المراجعة البصرية قبل التنفيذ

فُتحت صورتا `proof-decoded-390.png` و`proof-error-390.png` من دليل 13 نوفمبر. العنوان والمبلغ والصورة واضحون بالعربية؛ إعادة تحميل الصورة منفصلة عن إعادة تحميل الطلب. يوجد تمرير رأسي طبيعي ولا حاجة لإضافة شرح أو زينة. اعتماد الاتجاه الحالي؛ لا تعديل شكل سليم لمجرد الاختلاف. الإجراء الجديد مطلوب للتحقق من التطبيق المثبت والإيماءات والسياق، وهي فجوات معلنة في التقرير السابق.

المنتج: إدارة أكاديمية وتحصيل اشتراكاتها. الطابع: دقيق، هادئ، مباشر. البيئة: دفتر تحصيل الأكاديمية. موضع التركيز: مبلغ الطلب وصورته الخاصة. التفصيل المميز: مرجع الطلب ثابت في القراءة. نحتفظ بالعربية والخط والعلامة المعتمدة. منهج المراجعة: unslop، Damir Sokolovsky (@heydamir).

## البيانات والطريقة

محاكي iPhone واحد مؤقت على GitHub-hosted macOS؛ API وPostgreSQL وملفات الصور على نفس العامل وبقاعدة Demo جديدة. LegacyRegression بأكاديميتين مصطنعتين. إضافة هاتف تجريبي للإداري ومالك الأكاديمية الثانية وعضوية ثانية لمالك الأولى في القاعدة المؤقتة فقط. ينشئ ولي الأمر عبر API طلبين مصطنعين، أحدهما بباقة وصورة PNG محفوظة فعليًا والآخر دون باقة أو صورة. رفع الصورة برمجيًا تجهيز بيانات؛ لا يمثل اختبار منتقي ملفات iOS. لا تحويل أموال أو نشر staging.

يفتح الاختبار شاشة الإنتاج `NativeEnrollmentPaymentRead` في غلاف عربي بنفس الثيم. لا يمثل الوصول من الرئيسية. الأعطال 503 والبايتات التالفة والتأخير محقونة في نقل الصورة وحده؛ إعادة المحاولة الناجحة تنزل الأصل من API الفعلي. اختبارات الصلاحيات تستخدم الخادم الحقيقي دون محاكاة ردوده. فحص مالي كامل لصفوف التحصيل والإيصالات والفترات قبل وبعد؛ مقارنة تقرير المالك أيضًا.

## الحالات المكتوبة

لكل صف: البداية طلب Pending وصورة محفوظة من ولي أمر مرتبط بأكاديمية النجوم، إلا حين يُذكر غير ذلك. الأثر المتوقع على التقارير والتحصيل: لا تغيير. النتائج الفعلية والأدلة ستُضاف بعد التشغيل، دون مساواة الكتابة بالنجاح.

| الحالة | الإجراء / المصدر | الخطوات والنتيجة المتوقعة بالواجهة والخادم |
|---|---|---|
| IP01 | هوية الطلب ومبلغه — API تفاصيل الدفع | افتح مالك الأولى؛ الاسم والمرجع والمبلغ والعملة يطابقون الطلب المحفوظ، وحالته انتظار، بلا إيصال مدفوع. |
| IP02 | فشل الصورة — GET asset | احقن 503 مرة؛ رسالة عربية وإعادة تحميل، بلا تكبير ولا خلط مع عدم وصول إثبات. |
| IP03 | التعافي | اضغط إعادة تحميل؛ الصورة الأصلية تأتي من API ويطابق hash بايتات الرفع. تفاصيل الطلب لا تُعاد بلا حاجة. |
| IP04 | تكبير | اضغط تكبير بعد فك الصورة؛ المقياس 2 والصورة نفسها دون تنزيل جديد. |
| IP05 | سحب الصورة المكبرة | اسحب داخل الصورة؛ موضع التحويل يتغير فعليًا مع بقاء المقياس، دون تغيير الطلب أو التحصيل. |
| IP06 | الحجم الأصلي | اضغط الحجم الأصلي؛ التحويل يرجع identity والمقياس 1 دون تنزيل. |
| IP07 | إعادة الفتح | أزل الشاشة وافتح نفس الطلب؛ هوية وصورة الأصل نفسهما والمقياس 1. |
| IP08 | بايتات تالفة | افتح بحقن بايتات غير صورة؛ يعرض الخطأ بلا تكبير، ولا خطأ Flutter غير معالج. |
| IP09 | التعافي من التلف | أعد تحميل الأصل؛ يفك الصورة ويتيح التكبير دون تعديل الطلب. |
| IP10 | قراءة الإداري | افتح نفس الطلب بحساب الإداري الفعلي؛ نفس المبلغ والهوية والصورة دون عمليات مالية. |
| IP11 | ولي أمر آخر — تفاصيل | اطلب مسار ولي الأمر لنفس الطلب بهوية أسرة أخرى؛ 403/404 ولا بيانات. |
| IP12 | ولي أمر آخر — صورة | اطلب asset بهوية الأسرة الأخرى؛ 403/404 دون بايتات الأصل. |
| IP13 | مالك أكاديمية ثانية — تفاصيل | اطلب تفاصيل إدارة لنفس الطلب في سياق الثانية؛ 403/404. |
| IP14 | مالك أكاديمية ثانية — صورة | اطلب الصورة في سياق الثانية؛ 403/404 دون بايتات الأصل. |

| IP17 | منع بعد تبديل العضوية | بنفس جلسة المالك بعد التبديل اطلب تفاصيل الأولى وصورتها؛ رفض من الخادم. |
| IP18 | استعادة سياق صحيح | أعد اختيار عضوية الأولى وافتح الطلب مجددًا؛ الصورة تُقرأ بصلاحية جديدة ومقياس أصلي. |
| IP19 | الخروج مع صورة معلقة | افتح بعد حجز رد الصورة، سجل الخروج ثم حرر البايتات؛ لا تظهر صورة أو بيانات أو تكبير بعد الخروج. |
| IP20 | قابلية الاستخدام | راجع لقطات المحاكي الفعلية للخطأ والصورة والتكبير والطلب الفارغ والسياق الملغى؛ لا clipping/overflow أو رسالة تقنية؛ سجل حكمًا بصريًا منفصلًا. |

| IP24 | عرض كبير | افتح نفس الطلب عند textScale=2 على المحاكي؛ المبلغ وإعادة تحميل الصورة يصل لهما التمرير ويعملان بلا Flutter layout exception. |
