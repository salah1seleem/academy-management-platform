# سياسة اختيار موديل كوديكس وضبط نطاق العمل

تاريخ المراجعة: 28 سبتمبر 2026.
هذه سياسة عمل مقترحة استجابة لطلب صلاح، وليست ضماناً لحصة أسبوعية أو وصفاً لتكلفة حسابه الفعلية.

## مع كل برومبت

تضاف بطاقة: رقم المهمة، الموديل الموصى به، مستوى التفكير، السبب، ما الذي لا يُنفذ، ونقطة التوقف.
الاختيار يتم من إعدادات كوديكس الفعلية؛ لا نفترض أن نص البرومبت يغيّر الموديل أو الإعدادات.

## المهمة الأولى

Prompt 01: GPT-6 Sol / High.
السبب: تصميم العلاقات والصلاحيات وعزل الأكاديميات مع ضبط النطاق، دون تكلفة تشغيل بنية أو بناء كل الموديولات.
لا نبدأ هذه المهمة بـAstra أو Extra High أو Max/Ultra، ولا نشغّل subagents.

## قاعدة توزيع العمل اللاحق — توصية وليست مصفوفة أسعار

- مهام صغيرة واضحة وبيانات أو تعديل واجهة محدود: GPT-6 Luna / High كنقطة بداية، مع تحقق مناسب.
- تنفيذ جزء معتمد محدود وعابر لعدة ملفات: GPT-6 Sol / Medium.
- قرارات معمارية أو صلاحيات أو اشتراكات/تحصيل حساس: GPT-6 Sol / High.
- عائق صعب ثبت بعد فحص موجه: تصعيد للجزئية المتعثرة فقط إلى Sol / Extra High أو Astra / Light وفق طبيعة المشكلة، لا إعادة تنفيذ المشروع كله.
- Pro/Max/Ultra ليست إعداداً افتراضياً. لا تستخدم تسمية غير ظاهرة في حساب المستخدم، ولا تفترض أن مستوى الجهد متماثل بين الأجيال.

## حفظ الميزانية دون خفض الجودة

مهمة واحدة محددة، قراءة المرجع كاملاً مرة ثم قراءات موجهة، لا إعادة نسخ المستند في الإجابة، لا إعادة تحليل الفيديو مع كل مهمة، ولا تكرار محاولات بيئة معطلة بلا تشخيص.
تقترن كل ميزة باختبار وبيانات عرض؛ لا تُحذف الاختبارات الأمنية أو مراجعة العزل بحجة الاقتصاد.
لا تشغيل متوازٍ أو مراجعات آلية لا نهائية أو تغيير تلقائي للموديل. مراجعة واحدة محددة الأدلة لكل دفعة ثم توقف.
يسجل STATUS.md ما أُنجز وما ينتظر القرار لمنع إعادة الشغل.

## الحد الأسبوعي والـReset

لا توجد نسبة استهلاك ثابتة يمكن ضمانها لكل موديل أو برومبت. حجم السياق، الموديل، مستوى التفكير، الأدوات، زمن المهمة وغيرها تؤثر على الاستهلاك.
تُراجع Usage الفعلية ووقت إعادة التعيين والصلاحية المعروضة قبل استخدام الـReset الاحتياطي. لا تدّعي الأداة أنها رأت رصيداً لم تتحقق منه.
احتفظ بالـReset للطوارئ ضمن صلاحيته؛ هذه توصية تنظيمية وليست وعداً بأن الرصيد سيكفي الأسبوع.
