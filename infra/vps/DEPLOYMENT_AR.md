# تجهيز iAcademy One على VPS

هذه حزمة تجهيز ومراجعة فقط. لا شراء ولا نشر ولا DNS ولا استخدام لبيانات العملاء. الإنتاج غير مقبول حتى إغلاق العوائق أدناه ونجاح فحوصات PR؛ لا تدمج تلقائيًا.

## المصدر وحفظ العمل

فُحصت جميع فروع origin بعد fetch، بالتاريخ والـancestry ومحتوى الملفات. أحدث commit مرفوع `7e05d60` على `codex/15-native-mobile-app` في 21 أكتوبر 2026. `codex/16-unified-native-experience` عند `a75d7c2` بتاريخ 6 أكتوبر، وله commit متفرع واحد؛ لا يدل رقمه على حداثته. main عند `abda1ed` أقدم من تنفيذ المنتج. أُبقيت الفروع الأصلية دون تغيير.

النسخة المحلية أحدث من المرفوع: متطلبات V5.21 وتعديلات المصدر والاختبارات وmigrations حتى 30 أكتوبر. حُفظت 2004 ملفات متغيرة/غير متتبعة في أرشيف محلي خارج Git قبل العمل. يتضمن PR المصدر الحالي والمتطلبات الموجودة دون إعادة كتابة موافقتها، ويحفظ الملفات الخام محليًا. لا يشمل output أو أرشيفات المراجع أو صور الأطفال المرجعية الخاصة أو نسخ DB أو أسرارًا. المصدر الحالي يعيد استخدام مسارات ولي الأمر والتجديد وتعدد الرياضات الأحدث؛ لا نستبدله بواجهة الفرع 16 الأقدم.

## الخدمات والتخزين

- PostgreSQL 17 دون منفذ منشور، volume للبيانات، وhealth check بـpg_isready.
- migrate: صورة API نفسها مع `--migrate-only`؛ ينفذ migrations ثم يخرج دون listener أو workers أو seed. فشل migration يمنع تشغيل API. يملك اتصال DDL مستقلًا. لا تُنفذ migrations على قاعدة مستخدمة قبل backup ومراجعة SQL وتجربة الاستعادة.
- API: ASP.NET Core 10 كمستخدم app، مع ffmpeg/ffprobe للوسائط. عامل الاستيراد القائم داخل API، دون خدمة استيراد إضافية. readiness للـDB وliveness منفصلان.
- Web: Next.js 16، صورة standalone بدون dev server، وrewrites مبنية إلى `http://api:8080`؛ إعداد الرابط وقت التشغيل وحده لا يغيّر build سابقًا. `/api` من نفس origin لتفادي CORS وتسريب cookies.
- volumes منفصلة للوسائط الخاصة `/data/media` ومفاتيح Data Protection `/data/keys`. سجلات الجلسات نفسها في PostgreSQL. لا تقدم هذه المجلدات كملفات عامة. مفاتيح XML أسرار يجب تشفير نسخها الاحتياطية وتأمين قرص المضيف.
- Web متاح على loopback فقط. يلزم reverse proxy مع HTTPS على المضيف؛ نموذج nginx في هذا المجلد، وليس إعداد TLS مكتملًا أو مطبقًا. يزيل الـproxy قيم forwarded القادمة من العميل. API يثق فقط بعنوان Web الثابت `172.29.81.3`، ForwardLimit=1. الشبكة المحجوزة `172.29.81.0/24` يجب ألا تتعارض مع VPS. لا تشغل مشروعين بهذه الشبكة في الوقت نفسه.
- حساب runtime `iacademy_app` يملك CRUD وsequence usage دون DDL أو superuser. init-db.sh يهيئ الصلاحيات على volume جديد. مستخدم PostgreSQL الإداري مخصص للتهيئة والمهاجرات والنسخ والاستعادة، ولا يمرر إلى API. تغيير كلمة المرور في .env لا يغيّر مستخدمًا قائمًا تلقائيًا.

## إعداد قابل للمراجعة، عند السماح بالنشر لاحقًا

من جذر نسخة نظيفة من commit الإصدار، على مضيف به Docker Engine وCompose v2+:

```bash
cp infra/vps/.env.example .env
chmod 600 .env
# ضع كلمتين مختلفتين مولدتين محليًا؛ استخدم openssl rand -hex 32 لكل واحدة.
# اختر IMAGE_TAG يمثل commit الإصدار. لا تحفظ .env في Git.
docker compose config --quiet
docker compose build
docker compose up -d --wait --wait-timeout 240
docker compose ps -a
```

لا تطبع `docker compose config` بدون `--quiet` في السجلات لأنه يوسّع الأسرار. لا تغيّر Production إلى Demo للتحايل على الدخول. حافظ على `Demo__SeedEnabled=false` و`Demo__FixedOtpEnabled=false` وبوابة الدفع الداخلية معطلة. بناء الصور واختبارها في CI محلي للـrunner، بلا registry أو خادم أو DNS.

للترقية لاحقًا: backup، مراجعة migrations، build لصورة موسومة بـcommit، إيقاف Web وAPI لإيقاف الكتابات والعامل، ثم `docker compose run --rm migrate`، ثم إعادة إنشاء API وWeb وانتظار health. `docker compose up` الأول يطبق migration على DB جديدة؛ لا تعتمد على container migrate قديم exited(0) للترقية. إعادة التنفيذ آمنة عبر سجل EF migration وقفل PostgreSQL. لا تستخدم `down -v` على بيئة محفوظة. الرجوع إلى image قديم لا يرجع schema؛ الاستعادة إلى بيئة جديدة هي مسار الرجوع الآمن بعد migration غير متوافق.

## النسخ الاحتياطي والاسترجاع

من نفس root و.env الخاص بالبيئة، مع تصدير COMPOSE_PROJECT_NAME وIMAGE_TAG بالقيم المطابقة لملف .env:

```bash
infra/vps/backup.sh /absolute/private/backup-YYYYMMDD-HHMMSS
```

يوقف Web وAPI وكل عامل مضمن، ثم pg_dump بصيغة custom وأرشيف للوسائط والمفاتيح، ويكتب checksums واسم المشروع ووسم الصورة، ثم يعيد تشغيل الخدمتين. فشل أي خطوة يفشل الأمر ويعيد التشغيل؛ النسخة الجزئية ليست نسخة ناجحة. لا ينسخ .env. لا تنشر الأرشيفات في Git أو مجلد web. يلزم لاحقًا جدولة مؤمنة ونسخة مشفرة خارج VPS وسياسة احتفاظ وقياس RPO/RTO؛ لم تُنشأ automation أو خدمة مدفوعة.

للتجربة أو التعافي: نفس image/tag، ملف أسرار جديد، مشروع وvolumes جديدة، ولا تتصل مطلقًا بقاعدة مستخدمة. أوقف شبكة المشروع المصدر أولًا بسبب subnet الثابت؛ هذا لا يحذف volumes. صدّر COMPOSE_PROJECT_NAME جديدًا، POSTGRES_DB ومفاتيح DB وWEB_PORT المناسبين ثم:

```bash
infra/vps/restore.sh /absolute/private/backup-YYYYMMDD-HHMMSS
docker compose up -d --wait --wait-timeout 240
```

يرفض restore مشروع المصدر أو حاويات تطبيق قائمة أو DB غير فارغة أو وسائط/مفاتيح موجودة. يستعيد DB ذريًا دون clean، ثم الملفات. استخدم نسخًا موثوقة فقط، وليست أرشيفات من الإنترنت. الاسترجاع ليس ذريًا بين DB والملفات؛ عند الفشل اترك الهدف معزولًا وابدأ بهدف جديد. لا تحوّل المرور إليه قبل مراجعة المالك والإداري والمدرب وولي الأمر، وعزل أكاديمية ثانية، واستمرار الوسائط والجلسة بعد restart. بعد استعادة نسخة إنتاج في بيئة اختبار، اعزل الشبكة وامنع كل إرسال خارجي وامسح/أبطل الجلسات قبل السماح بالوصول؛ لا تستعمل بيانات عملاء في اختبار الديمو.

## الديمو والأدوار

اختبارات Playwright الحالية تهيئ LegacyRegression ببيانات مصرية خيالية ثابتة وأكاديمية ثانية، وكلمات مرور وأرقام `.test` معروفة. اختبارات Football منفصلة، وseed idempotent. لا يحوّل Compose الإنتاج إلى demo تلقائيًا ولا يزرع مستخدمين. رحلة القبول: المالك يدخل ويراجع التحصيل والاشتراكات؛ الإداري يسجل لاعبًا ويحصّل مرة واحدة؛ المدرب يدخل بمجموعاته فقط ويسجل الحضور/التقييم؛ ولي الأمر يدخل بـOTP العرض ويرى أطفاله فقط. بيانات الدخول التجريبية للأدوار في tests/e2e/support وملفات Demo الحالية، وليست بيانات إنتاج.

## عوائق الإنتاج

1. لا يوجد مزود SMS/OTP إنتاجي: طلب OTP يعيد 501 بالعربية في Production. دخول ولي الأمر والمدرب/الموبايل للعملاء محجوب حتى تنفيذ مزود حقيقي، انتهاء/محاولات/إعادة إرسال ومراقبة التسليم واختبارات إساءة الاستخدام. لا تفعّل fixed OTP لعملاء حقيقيين.
2. تجهيز آمن لأول Platform Administrator وMFA/استعادة الحساب، وأول عضويات المالك والإداري. لا توجد كلمة مرور تمهيدية في migration أو Compose.
3. HTTPS وشهادة صالحة وhost/origins وWebAuthn RP ID الفعلية، وتحقق forwarded headers وSecure cookies على staging. نموذج nginx يحتاج تثبيتًا ومراجعة خاصة بالمضيف.
4. قنوات push والدفع الخارجي والتخزين/النسخ المشفر ومراقبة التشغيل وموارد VPS وسياسة الصيانة تحتاج إعدادًا وقبولًا مستقلين. لا تعني صحة health نجاح هذه التكاملات.
5. لا قبول قبل نجاح جميع checks المطلوبة في PR، واختبار استعادة ودوام جلسة ووسائط ورحلات أدوار في staging معزول. تفاصيل ما شُغّل فعلًا في VALIDATION_AR.md؛ لا وصف production-ready.
